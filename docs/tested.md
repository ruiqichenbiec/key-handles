# 测过什么，怎么测的

## 环境

- Windows 11
- Claude Code 命令行 2.1.308
- 模型：Haiku
- 密钥：全部是假密钥，例如 `sk-ant-api03-FAKE-DEMO-KEY-0123456789abcdef`

## 方法

交互界面的测试由脚本通过 Windows 伪终端（ConPTY）驱动：脚本启动 `claude`（不带 `-p`），在输入框里逐字输入，或者用终端的粘贴序列粘贴。会话结束后，脚本在三个地方搜索假密钥的原文：

1. 这次会话的记录文件 `~/.claude/projects/…/<session>.jsonl`
2. 输入历史 `~/.claude/history.jsonl`
3. 会话期间 `~/.claude` 下被写过的所有其他文件

模型拿到了什么，看两处：模型的回复，和会话记录里发给模型的那条消息。

## 结果

### 对照：不带插件

| 输入 | 模型回复 | 会话记录里的原文 | 输入历史里的原文 |
|---|---|---|---|
| 逐字输入一条带假密钥的消息 | 复述了密钥原文 | 6 处 | 1 处 |

### 带插件，终端交互界面

| 情况 | 模型回复 | 会话记录里的原文 | 输入历史里的原文 |
|---|---|---|---|
| 逐字输入带密钥的消息 | 代号 | 0 | 0 |
| 粘贴三行，其中一行是密钥 | 代号 | 0 | 0 |
| 粘贴 31 行配置（界面折叠显示） | 代号 | 0 | 0 |
| Bash 输出里有密钥 | 代号 | 0 | 不适用 |
| Read 读到的文件里有密钥 | 代号 | 0 | 不适用 |
| 模型在命令里写代号，执行时换回 | 代号；磁盘上的文件里是真实密钥 | 0 | 0 |

会话期间 `~/.claude` 下被写过的其他文件里，也没有找到密钥原文。

界面上看到的：按回车之前，输入框里是密钥原文；提交之后，对话区里显示的是代号。

### 带插件，无界面模式（`claude -p`）

提交时替换、Bash 输出、Read 读文件、执行时换回，四项结果和上表一致。

### 守卫出错时

| 写法 | 结果 |
|---|---|
| 守卫出错，没有写兜底 | 密钥原样进了模型和会话记录。默认是出错放行 |
| 守卫出错，写了兜底 | 这条消息被丢弃，没有泄露 |

`prototype/` 里提交这一步写了兜底。工具调用那一步还没有。

### 只用本地代理（改 `ANTHROPIC_BASE_URL`）

代理能让模型只看到代号，但本机的会话记录里仍然有密钥原文（7 处）。所以这个原型走的是插件，不是代理。

## 没有测的

- Claude 桌面应用
- macOS、Linux
- 2.1.308 以外的 Claude Code 版本
- 编码过的密钥（base64 等）、被拆成多行的密钥、图片里的密钥
- 子 agent、MCP 工具
- 输入时就遮蔽（现在是提交时才遮蔽）
- 真实密钥、各家接口的真实调用
